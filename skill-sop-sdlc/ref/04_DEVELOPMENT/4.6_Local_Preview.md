# 4.6 Local Preview — แสดงตัวอย่างแอปที่รันจริง

## วัตถุประสงค์

หลังพัฒนาเสร็จ (และ **ก่อน** Deploy) ให้ skill **รันแอปบนเครื่อง local แล้วเปิดให้ user เห็นแอปที่ทำงานจริง** — เพื่อให้ผู้ใช้ที่ไม่ใช่ dev ได้ **เห็นและอนุมัติ (approve)** ก่อนนำขึ้น Production. ขั้นตอนนี้เป็น **review/approval gate** ไม่ใช่การ Deploy — ยังไม่มีอะไรขึ้น server จริง เป็นแค่การให้ user ดูของจริงบน `http://localhost:5173` ก่อนตัดสินใจไปต่อ

> **💡 กฎสำคัญ (Auto-Run & Continuous Preview):** เพื่อให้ user/orchestrator สามารถเข้าตรวจหน้าตาแอปได้ตลอดเวลา ให้ developer agent **รันทั้ง backend และ frontend dev servers ขึ้นมาโดยอัตโนมัติตั้งแต่เริ่มเขียนโค้ด (Phase 4)** และเปิดทิ้งไว้ใน background เสมอตลอดช่วงการทำงาน (ไม่ใช่รันแค่ตอนจบเฟส)

---

## 1. Prerequisites

- [ ] Backend ติดตั้ง dependencies แล้ว (`cd backend && npm install`)
- [ ] Frontend ติดตั้ง dependencies แล้ว (`cd frontend && npm install`)
- [ ] ตั้งค่า `.env` แล้ว (copy จาก `.env.example` — ดู [4.1 §5](4.1_Project_Initialization.md))
  - Backend: `ALLOWED_ORIGINS=http://localhost:5173`
  - Frontend: `VITE_API_URL=http://localhost:5000/api`
- [ ] Database เข้าถึงได้ (PostgreSQL) — `DATABASE_URL` + `DATABASE_URL` ใส่ค่าจริงแล้ว เพื่อให้หน้าจอที่ดึงข้อมูล (data-backed screens) แสดงผลได้

---

## 2. Start the servers

รัน backend **ก่อน** แล้วค่อยรัน frontend — ใช้ 2 terminal (เหมือน [4.5 §4](4.5_Frontend_Integration.md)):

```bash
# Terminal 1: Backend (รันก่อน)
cd backend && npm run dev
# ตรวจว่า http://localhost:5000/api/health ตอบ OK
curl http://localhost:5000/api/health
```

```bash
# Terminal 2: Frontend (รันหลัง backend ขึ้นแล้ว)
cd frontend && npm run dev
# เปิด http://localhost:5173
# (หรือใช้คำสั่ง Simple Browser: Show ใน IDE เพื่อแสดงตัวอย่างใน Sidebar)
```

> backend ต้องขึ้นก่อน ไม่งั้น frontend จะเรียก API ไม่ได้ และหน้าจอ data-backed จะว่างเปล่า

---

## 3. Present the preview to the user

- เปิดแสดงตัวอย่าง (Preview) ในแถบข้าง (Sidebar) ของ IDE โดยเรียกเปิด Command Palette  พิมพ์หาคำสั่ง **`Simple Browser: Show`** แล้วป้อน `http://localhost:5173` หรือแชร์ URL นี้ให้ user เปิดดูในเบราว์เซอร์
- พา user เดินผ่าน **หน้าจอหลัก** ทีละหน้า โดยอ้างอิงกับ requirements / acceptance criteria ที่อนุมัติไว้ — แต่ละหน้าควร map กับสิ่งที่ตกลงกันใน Phase 1
- ยืนยันว่าทุกหน้าจอที่ดึงข้อมูลแบบ async แสดง **loading / empty / error** states ครบ (ตามกติกาออกแบบใน Phase 2)
- ให้ user ลองทำ flow จริง (เช่น Login → ดูข้อมูล → สร้าง/แก้ไข) แล้วถามว่า "ตรงกับที่ต้องการไหม"

## 4. Troubleshooting

| อาการ | สาเหตุ | วิธีแก้ |
|-------|--------|---------|
| **Port already in use** | มี process ใช้ `5000`/`5173` อยู่ | kill process เดิม หรือเปลี่ยน port (`PORT` ฝั่ง backend / `--port` ฝั่ง Vite) |
| **Blank page** (หน้าขาว) | env var ไม่ได้ตั้ง / `VITE_API_URL` ผิด | ตรวจ `.env` ฝั่ง frontend ว่า `VITE_API_URL=http://localhost:5000/api` แล้ว restart `npm run dev` (Vite อ่าน env ตอน start) |
| **CORS error** ใน console | `ALLOWED_ORIGINS` ไม่ครอบคลุม frontend | ตั้ง `ALLOWED_ORIGINS=http://localhost:5173` (ห้ามมี trailing slash) แล้ว restart backend |
| **Data not loading** | backend ไม่ได้รัน / PostgreSQL creds หาย | ตรวจ Terminal 1 ว่า backend ขึ้น + `/api/health` ตอบ OK และ `DATABASE_URL` ใส่ค่าจริง |

---

## 5. Preview Gate (✅ Checklist)

ต้องผ่านทุกข้อก่อนไป Phase 5 (Deploy):

- [ ] Server ขึ้นทั้ง 2 ฝั่ง (backend + frontend)
- [ ] `http://localhost:5000/api/health` ตอบ OK
- [ ] หน้า Home + ทุก core screen เข้าถึงได้บน `http://localhost:5173`
- [ ] ไม่มี error ใน browser console (เปิด DevTools → Console)
- [ ] หน้าจอ async แสดง loading / empty / error states ครบ
- [ ] **User ได้เห็น live preview และ approve แล้ว** ก่อนไปขั้น Deploy
