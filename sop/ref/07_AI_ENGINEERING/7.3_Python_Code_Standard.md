# 03 · Python Code Standard (SOP-DEV-PY-001)

## วัตถุประสงค์

มาตรฐานการเขียน Python ของทีม ใช้กับทุก zone (`apps/`, `packages/`, `research/`) เป้าหมายคือโค้ดที่ **อ่านเองรู้เรื่อง**: เห็นขอบเขตของแต่ละ function ได้ทันทีเวลา scroll, รู้ว่าแต่ละชื่อมาจาก module ไหน, และรู้ input/output ได้โดยไม่ต้องอ่าน body

มาตรฐานนี้มีสองชั้น:

- **ส่วน A — House rules** (ข้อ 1–4): สไตล์ของทีม **ชนะ** ทุกกฎทั่วไปที่ขัดกัน
- **ส่วน B — Clean-code rules** (ข้อ 5–12): ใช้ทุกข้อ ยกเว้นจุดที่ส่วน A กำหนดไว้แล้ว

# ส่วน A — House rules

## 1. OOP Based — เรียกกันผ่าน Object

- **component** ทุกตัว เช่น service, pipeline, adaptor, model wrapper, detector เป็น class ที่ถือ collaborator ของตัวเองไว้
- collaborator ส่งเข้ามาทาง `__init__` (dependency injection) — test จึงส่ง fake เข้าไปแทนได้
- component คุยกันโดยถือ reference ของ object อื่นแล้วเรียก method ไม่ใช่ส่ง dict ต่อกันเป็นทอด
- ตั้งชื่อ module ตามสิ่งนั้น ตั้งชื่อ class ตามบทบาท ให้อ่านต่อกันได้: `softpatch.SoftPatches()`, `golden.GoldenSelector()`

```python
# ❌ function ลอย ๆ ส่ง dict ต่อกันเป็นทอด
def run(cfg):
    feats = extract(cfg["images"], cfg["model"])
    return rank(feats, cfg["k"])
```

```python
# ✅ object ถือ collaborator และ state ของตัวเอง
import softpatch



class DataPreparationPipeline:
    """Turns a raw capture folder into a ranked training set."""

    def __init__(
        self,
        patches: softpatch.SoftPatches,
        keep: int,
        ) -> None:

        self._patches = patches
        self._keep = keep



    def run(
        self,
        ) -> list[str]:

        """
        Rank every capture by how normal it looks.

        Returns:
            Capture paths, most normal first, `keep` of them.
        """
        return self._patches.rank()[: self._keep]
```

**อะไรยังเป็น function ได้** (ตรงกับ promotion rubric ของ clean-code):

- transform ที่ไม่มี state เช่น expression ของ Polars, การคำนวณ metric, parser
- query module ใน `adaptor/db/` (connection ถูกส่งเข้ามา ไม่มี state ร่วม)
- data ล้วน ๆ ใช้ `dataclasses.dataclass(frozen=True)` หรือ Pydantic model ไม่ใช่ class เขียนเอง

**house override:** clean-code ทั่วไปบอกให้เปลี่ยน class ที่มีแค่ `__init__` กับ method เดียวเป็น function — ที่นี่ **ไม่เปลี่ยน** ถ้า `__init__` รับ collaborator เข้ามา (แบบ `DataPreparationPipeline` ด้านบน) เพราะนั่นคือจุดที่ swap และ fake ได้

**ยังห้าม:** class ที่แค่ส่งต่อ call ให้ object อื่น (shallow middle man), class ที่มีแต่ `@staticmethod` (namespace dump), factory ที่สร้างของได้ชนิดเดียว, interface ที่มี implementation เดียว — ดู port rule ใน 02

## 2. Import ทั้ง module แล้วเรียกผ่านชื่อ module

ชื่อหลัง `import` ต้องเป็น **module** เสมอ ไม่ใช่ class หรือ function

## 3. ระยะห่าง — 3 บรรทัดว่างระหว่าง def

- **3 บรรทัดว่าง** ก่อนทุก `def` และ `class` รวม method ใน class
- member ตัวแรกของ class หรือของ module ไม่ต้องเว้น (ไม่มีอะไรให้แยก)
- **ภายใน** function ใช้ 1 บรรทัดว่างแบ่งย่อหน้า (parse → validate → compute → return)
- เวลาแก้ไฟล์เดิมที่ใช้ระยะนี้ ห้าม "normalise" กลับเป็น PEP 8

```python
import polars as pl



class GoldenSelector:
    """Picks the medoid capture of each (model, view) group."""

    def __init__(
        self,
        canvas: int,
        ) -> None:

        self._canvas = canvas



    def select(
        self,
        features: pl.LazyFrame,
        ) -> pl.DataFrame:

        """
        Pick one golden capture per group.

        Args:
            features: One row per capture with its DINOv2 embedding.

        Returns:
            One row per (model, view) with the golden's path.
        """
        return features.group_by("model", "view").agg(pl.col("path").first()).collect()
```

**กับดัก formatter:** `ruff format` (และ black) ยุบเหลือ 2 บรรทัดที่ระดับ module และ 1 บรรทัดใน class โดยไม่มี option ให้ตั้ง — path ที่ใช้ house style นี้ต้องไม่ผ่าน `ruff format`: ใส่ใน `[tool.ruff.format] exclude` หรือไม่ใส่ใน task format ส่วน `ruff check` ยังต้องรันทุกที่

## 4. Signature และ Docstring

```python
    def edge_region(
        self,
        shape: tuple[int, ...],
        axis: int,
        sign: int,
        span: int,
        ) -> tuple[int, int, int, int]:

        """
        The strip `span` deep at one edge.

        Args:
            shape: Window shape, `(height, width, ...)`.
            axis: 0 if the edge runs across rows, 1 across columns.
            sign: -1 at the low index, +1 at the high.
            span: Strip depth in pixels.

        Returns:
            `(x0, y0, x1, y1)`, inclusive-exclusive like a NumPy slice.

        Raises:
            ValueError: When `span` is larger than the window.
        """
```

- parameter **บรรทัดละตัว** รวม `self` เพื่อให้อ่าน input จากบนลงล่าง
- `) -> ReturnType:` อยู่บรรทัดของตัวเอง เยื้องระดับเดียวกับ parameter
- **เว้น 1 บรรทัด** ระหว่าง signature กับ docstring; `"""` เปิดและปิดอยู่บรรทัดของตัวเอง
- คำอธิบายสั้น 1 บรรทัด → `Args:` → `Returns:` → `Raises:` (ถ้ามี) — แต่ละรายการบรรทัดเดียว
- **Args/Returns บอกความหมาย ไม่ใช่ type** — type อยู่ใน hint แล้ว ให้เขียนหน่วย ช่วงค่า รูปแบบ หรือที่มาแทน

```python
# ❌ ทวน type
#   image: Input image as numpy array.
# ✅ บอกสิ่งที่ type บอกไม่ได้
#   image: BGR capture, full sensor resolution.
```

- docstring ห้ามยาวกว่า body ของ function — เหตุผลยาว ๆ ไปไว้ใน markdown ข้างโค้ด
- `__init__` ที่แค่เก็บ collaborator และ test ที่ตั้งชื่อ `test_<unit>_<scenario>_<expected>` ไม่ต้องมี docstring
- type hint ทุก parameter และ return

# ส่วน B — Clean-code rules

## 5. Control flow และความยาว

- **guard clause + early return** — ห้ามซ้อนเกิน 3 ระดับ
- ห้าม `elif` / `else` ต่อจาก block ที่จบด้วย `return` หรือ `raise`
- Newspaper rule: public method อยู่บน, helper (`_private`) อยู่ล่างตามลำดับที่ถูกเรียก
- **บรรทัดละไม่เกิน 88 ตัวอักษร** ทั้งโค้ด comment และ docstring
- function ยาวไม่เกินหนึ่งหน้าจอ (~40–50 บรรทัด)
- ไฟล์ละ 100–300 บรรทัด; เกิน 400 ให้ลบ dead code และ docstring ที่เกินก่อน แล้วค่อยแยก module

```python
# ❌ arrowhead
if capture:
    if capture.regions:
        for region in capture.regions:
            if region.is_enabled:
                ...

# ✅ guard
if capture is None:
    raise errors.DomainError("Inspection not found", 404)

enabled = [region for region in capture.regions if region.is_enabled]
```

## 6. Naming (PEP 8)

| ชนิด | รูปแบบ | ตัวอย่าง |
|---|---|---|
| ตัวแปร, function, method | `snake_case`, function เป็นคำกริยา | `inspection_id`, `extract_battery_text()` |
| boolean | prefix เชิงบวก | `is_valid`, `has_mismatch`, `should_sync` (ห้าม `not_ready`) |
| private member | `_snake_case` | `self._reader`, `_sources()` |
| ค่าคงที่ | `UPPER_SNAKE_CASE` | `MIN_SHOTS`, `SELECT_CAPTURE` |
| class, Protocol | `PascalCase` คำนามของ domain | `InspectionService`, `OcrReader` |
| module | `snake_case` | `golden.py`, `hybrid_router.py` |
| package (dist) / (import) | `kebab-case` / `snake_case` | `battery-ocr` / `battery_ocr` |
| table, column | `snake_case` | ตาม `../../SKILL.md` Phase 3 |
| test | `test_<unit>_<scenario>_<expected>` | `test_parse_short_serial_raises` |

ชื่อภาษาอังกฤษที่มีความหมาย ไม่ย่อ (`x`, `tmp_res`, `b_id`, `arr`) — ยกเว้นตัวแปรในสูตรที่อ้างถึง paper

## 7. Comment

- comment ใส่เฉพาะบรรทัดที่ดูแล้วจะคิดว่าผิด (ค่าคงที่ที่วัดมา, ลำดับที่ไม่ชัด) 1–2 ประโยค
- ห้าม comment ที่อธิบายว่าโค้ด *ทำอะไร* — ให้ชื่อตัวแปรและ function บอกเอง
- ทางลัดที่ตั้งใจ: `# ponytail: <ทำไม + ทางอัปเกรด>`

## 8. Zero hardcoding

- port, host, URL, path, timeout, ชื่อ model มาจาก `config.Settings` (pydantic-settings) เท่านั้น และลงทะเบียนใน `.env.example`
- magic number / string ใน logic → ค่าคงที่ `UPPER_SNAKE_CASE` ที่หัวไฟล์ หรือ `enum.StrEnum`; ค่าคงที่ที่เกี่ยวกันรวมเป็น frozen dataclass
- path ใช้ `pathlib.Path(__file__).parents[...]` หรือ root จาก settings — ห้าม `"/data/..."`, `os.path.join`
- multiline string (SQL, prompt) ใช้ `"""` ไม่ใช้ `\` ต่อบรรทัดหรือต่อ string ในวงเล็บ

## 9. Library-first

ก่อนเขียน helper เอง ไล่ตามลำดับ:

1. `packages/*` ใน monorepo มีอยู่แล้วหรือยัง
2. stdlib: `pathlib`, `itertools`, `functools`, `collections`, `dataclasses`, `enum`, `json`, `tomllib`, `urllib.parse`, `datetime.fromisoformat`
3. dependency ที่ติดตั้งแล้ว: `polars`, `pydantic`, `httpx`, `cv2`

ห้าม parse format ที่มีโครงสร้าง (URL, วันที่, JSON, ตาราง) ด้วย slicing หรือ regex เอง ถ้า library แก้ได้ใน 1–3 บรรทัด การเขียน algorithm เองถือว่า over-engineering

## 10. Data — Polars first พร้อม lineage

- `polars` แทน `pandas` ทุกที่; `LazyFrame` (`scan_*`) แล้ว `.collect()` ครั้งเดียวตอนท้าย
- ประกาศ `schema={...}` หรือ `schema_overrides={...}` ทุกครั้งที่อ่านหรือสร้าง frame
- expression `pl.col(...)`, `group_by`, `pl.when().then().otherwise()` — ห้าม `iter_rows()`, loop ทีละแถว, `.to_pandas()`, แก้ frame in-place
- **ข้อมูลที่ส่งออก** (Parquet, DuckDB, eval split) ต้องมีคอลัมน์ lineage: `_source_id`, `_source_file`, `_batch_id` (UUIDv4), `_processed_at` (UTC), `_pipeline_version` (git commit)
- ข้อมูลดิบ (Bronze) ห้ามแก้หรือลบ — ทุกขั้นสร้างตารางใหม่, เก็บ key เดิม (ชื่อไฟล์, bbox ต้นฉบับ, เวลาถ่าย) ไว้เสมอ

```python
import datetime
import uuid

import polars as pl



def tag_lineage(
    frame: pl.LazyFrame,
    source_file: str,
    pipeline_version: str,
    ) -> pl.LazyFrame:

    """
    Stamp a transformed frame with where and when it came from.

    Args:
        frame: Rows derived from `source_file`, one per record.
        source_file: DVC path or URI of the raw input.
        pipeline_version: Git commit of the code that produced the rows.

    Returns:
        The same rows with the lineage columns appended.
    """
    return frame.with_columns(
        pl.lit(source_file).alias("_source_file"),
        pl.lit(str(uuid.uuid4())).alias("_batch_id"),
        pl.lit(datetime.datetime.now(datetime.UTC)).alias("_processed_at"),
        pl.lit(pipeline_version).alias("_pipeline_version"),
    )
```

## 11. Error และ log

- error ของ domain เป็น class (เช่น `entities/errors.py`) ห้าม raise `Exception` เปล่า ๆ
- ห้าม `except:` เปล่า และห้ามกลืน error โดยไม่ log
- ใช้ `logging.getLogger(__name__)` ไม่ใช้ `print()` ใน `apps/` และ `packages/` (`research/` ใช้ `print` ได้)
- ห้าม log หรือส่ง secret, password, token ออกไป
