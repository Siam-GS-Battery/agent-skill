# 02 · Clean Architecture Backend (Python)

## วัตถุประสงค์

ให้ Python backend ทุกตัวมีโครงเดียวกัน เพื่อให้ developer คนอื่นต่อ module ใหม่ได้โดย **เขียน adaptor ตัวเดียว** ไม่ต้องรู้ทั้งระบบ — business logic อยู่ตรงกลาง สิ่งภายนอกทั้งหมด (HTTP, DB, S3, MQTT, model server, ระบบของ vendor) อยู่ขอบนอก

> หลักการ: *"source code dependencies can only point inwards"* — Robert C. Martin, The Clean Architecture

---

## 1. Layer และทิศทาง

```
          ┌──────────────────────────────────────────┐
          │ adaptor/  (http · db · s3 · mqtt · ocr)  │   ขอบนอก: framework, I/O
          │   ┌──────────────────────────────────┐   │
          │   │ use_cases/   service classes     │   │   business logic
          │   │   ┌──────────────────────────┐   │   │
          │   │   │ entities/  + interfaces/ │   │   │   model, error, port
          │   │   └──────────────────────────┘   │   │
          │   └──────────────────────────────────┘   │
          └──────────────────────────────────────────┘
   main.py + adaptor/http/deps.py = composition root (ที่เดียวที่ประกอบทุกชิ้นเข้าด้วยกัน)
```

| Layer | มีอะไร | import ได้ | ห้าม |
|---|---|---|---|
| `entities/` | Pydantic models (request/response/domain), `errors.py`, enum, value object | stdlib, pydantic | ทุก layer ด้านบน |
| `interfaces/` | port เป็น `typing.Protocol` | `entities` | `adaptor`, `use_cases` |
| `use_cases/` | service class — logic ทั้งหมด | `entities`, `interfaces`, `adaptor/db` (query module) | `fastapi`, SQL string, `adaptor/http` |
| `adaptor/http/` | router (controller), `deps.py`, pagination | `use_cases`, `entities` | `adaptor/db` โดยตรง (ยกเว้น `deps.py`) |
| `adaptor/db/` | SQL แบบ parameterized + connection pool | `entities` | `use_cases` |
| `adaptor/<system>/` | client ของระบบภายนอก ที่ implement port | `entities`, `interfaces` | `use_cases` |

**ไม่มี repository layer แยก** เมื่อใช้ SQL ตรง (psycopg) — query module ใน `adaptor/db/` *คือ* repository การเพิ่มอีกชั้นแค่ย้าย string ไปมา (Cosmic Python: pattern นี้คุ้มเมื่อ domain ซับซ้อน ไม่ใช่กับ CRUD)

## 2. โครงไฟล์

```text
apps/backend/src/app/
├── main.py              # create_app(), lifespan, exception handler → SOP envelope
├── config.py            # class Settings(BaseSettings)
├── entities/
│   ├── __init__.py      # re-export model ที่ใช้ข้ามโมดูล
│   ├── common.py        # ApiSuccess[T], Pagination
│   ├── errors.py        # DomainError(message, status)
│   └── <area>.py
├── interfaces/
│   └── <system>.py      # class <System>Reader(Protocol)
├── use_cases/
│   └── <area>.py        # class <Area>Service
└── adaptor/
    ├── http/
    │   ├── deps.py      # Depends(): สร้าง service, เลือก adaptor, auth guard
    │   └── <area>.py    # router = APIRouter(prefix="/<area>")
    ├── db/
    │   ├── pool.py
    │   └── <area>.py    # async def select_<x>(connection, ...) -> list[dict]
    └── <system>/
        └── <impl>.py    # class <System>Http / <System>Sql
```

- ที่ root ของ `app/` มีได้แค่ `__init__.py`, `main.py`, `config.py`
- หนึ่งพื้นที่ธุรกิจ (area) = ไฟล์ชื่อเดียวกันในแต่ละ layer: `entities/users.py`, `use_cases/users.py`, `adaptor/db/users.py`, `adaptor/http/users.py`

## 3. Port กับ Adaptor — เมื่อไหร่ต้องมี port

**Adaptor** คือวิธีที่ app นี้ต่อกับ module หรือระบบอื่นทุกตัว ทุกการต่อภายนอกต้องผ่าน `adaptor/<system>/` เสมอ

**Port** (`interfaces/<system>.py`) ต้องมีเหตุผล — สร้างเมื่อเข้าข้อใดข้อหนึ่ง:

1. ระบบนั้น **ไม่ใช่ของเรา** (vendor, ทีมอื่น) และสัญญายังอาจเปลี่ยน
2. **ยังไม่ได้ตัดสินใจ** ว่าจะต่อแบบไหน (SQL view? HTTP API? MSSQL?)
3. มี implementation ตัวที่สองจริง ๆ เช่น fake สำหรับ test หรือ model server สองแบบ

ถ้าไม่เข้าข้อไหนเลย ให้ class ของ adaptor เป็นสัญญาเอง ไม่ต้องมี Protocol — implementation เดียวไม่ต้องมี abstract base

ใช้ `typing.Protocol` (PEP 544) ไม่ใช้ `abc.ABC`: adaptor ไม่ต้อง inherit แค่มี method ตรงกัน type checker ก็ตรวจให้

```python
# interfaces/ocr.py
import typing

from app import entities



class OcrReader(typing.Protocol):
    """What the backend needs from an OCR model server."""

    async def read(
        self,
        image: bytes,
        region: entities.Region,
        ) -> entities.OcrResult:

        """
        Read the text inside one region of an image.

        Args:
            image: Encoded capture (PNG or JPEG).
            region: Box to read, in image pixels.

        Returns:
            The text and its confidence.
        """
        ...
```

```python
# adaptor/ocr/sglang.py
import httpx

from app import entities

OCR_ROUTE = "/v1/ocr"


class SglangOcr:
    """OcrReader over the shared SGLang model server."""

    def __init__(
        self,
        client: httpx.AsyncClient,
        model: str,
        ) -> None:

        self._client = client
        self._model = model



    async def read(
        self,
        image: bytes,
        region: entities.Region,
        ) -> entities.OcrResult:

        """
        Ask the model server for the text in one region.

        Args:
            image: Encoded capture (PNG or JPEG).
            region: Box to read, in image pixels.

        Returns:
            The text and its confidence.

        Raises:
            httpx.HTTPStatusError: When the model server answers an error status.
        """
        payload = region.payload(image, self._model)
        response = await self._client.post(OCR_ROUTE, json=payload)
        response.raise_for_status()
        return entities.OcrResult.model_validate(response.json())
```

`deps.py` เป็นที่เดียวที่รู้ว่าใช้ `SglangOcr` — use case รู้แค่ `OcrReader` เมื่อเปลี่ยน model server ก็เขียน adaptor ใหม่แล้วแก้ `deps.py` บรรทัดเดียว

`httpx.AsyncClient` สร้างครั้งเดียวใน lifespan (`base_url` และ timeout มาจาก `Settings`) แล้วส่งเข้า adaptor — ห้ามสร้าง client ใหม่ทุก request

**ต่อกับ app อื่น** ก็ใช้วิธีเดียวกัน: app ไม่ import กัน แต่เขียน adaptor ที่คุยกับ HTTP route หรือ MQTT topic ของอีก app เช่น `adaptor/mqtt/` สำหรับส่งคำสั่งให้ edge controller

**ต่อกับ package ส่วนกลาง:** use case เรียก class หรือ function ใน `packages/` ได้ตรง ๆ (`from inspection_domain import judgement`) ไม่ต้องมี adaptor เพราะ package เป็น pure logic ที่ไม่มี I/O ถ้า package โหลด model หนัก ๆ ให้สร้าง object ครั้งเดียวใน lifespan แล้วส่งเข้า use case ผ่าน `deps.py`

## 4. ตัวอย่าง endpoint ครบทุก layer

**entities/inspections.py** — สัญญาของข้อมูล (แทน Zod)

```python
import pydantic



class JudgeRequest(pydantic.BaseModel):
    inspection_id: int = pydantic.Field(gt=0)
```

**use_cases/inspections.py** — logic, รับ collaborator ทาง `__init__`

```python
import psycopg

from app import entities
from app.adaptor.db import inspections
from app.entities import errors
from app.interfaces import ocr



class InspectionService:
    """Judges inspections against their configured regions."""

    def __init__(
        self,
        connection: psycopg.AsyncConnection,
        reader: ocr.OcrReader,
        ) -> None:

        self._db = connection
        self._reader = reader



    async def judge(
        self,
        inspection_id: int,
        ) -> entities.Verdict:

        """
        Read and judge every region of one inspection.

        Args:
            inspection_id: `inspection.id` in our schema.

        Returns:
            The verdict, one entry per region.

        Raises:
            errors.DomainError: 404 when the inspection does not exist.
        """
        capture = await inspections.select_capture(self._db, inspection_id)
        if capture is None:
            raise errors.DomainError("Inspection not found", 404)

        results = [await self._reader.read(capture.image, r) for r in capture.regions]
        return entities.Verdict.from_results(results)
```

**adaptor/db/inspections.py** — SQL เท่านั้น, parameterized เสมอ

```python
import psycopg
from psycopg import rows

SELECT_CAPTURE = """
    SELECT id, image_path, regions
    FROM sgs.inspection
    WHERE id = %(inspection_id)s
"""



async def select_capture(
    connection: psycopg.AsyncConnection,
    inspection_id: int,
    ) -> dict | None:

    """
    Load one inspection's capture and regions.

    Args:
        connection: Open connection from the pool.
        inspection_id: `inspection.id`.

    Returns:
        The row, or None when there is no such inspection.
    """
    async with connection.cursor(row_factory=rows.dict_row) as cursor:
        await cursor.execute(SELECT_CAPTURE, {"inspection_id": inspection_id})
        return await cursor.fetchone()
```

> query module เป็น function ได้: ไม่มี state ร่วม และ connection ถูกส่งเข้ามา — ตรงกับข้อยกเว้น "one-line helper" ของกฎ OOP

**adaptor/http/inspections.py** — controller บาง

```python
import typing

import fastapi

from app import entities
from app.adaptor.http import deps
from app.use_cases import inspections

router = fastapi.APIRouter(prefix="/inspections", tags=["inspections"])
ServiceDep = typing.Annotated[
    inspections.InspectionService, fastapi.Depends(deps.get_inspection_service)
]



@router.post("/judge", response_model=entities.ApiSuccess[entities.Verdict])
async def judge(
    body: entities.JudgeRequest,
    user: deps.CurrentUser,
    service: ServiceDep,
    ) -> entities.ApiSuccess[entities.Verdict]:

    """
    Judge one inspection.

    Args:
        body: The inspection to judge.
        user: The authenticated caller.
        service: The inspection service.

    Returns:
        The verdict in the SOP success envelope.
    """
    return entities.ApiSuccess(data=await service.judge(body.inspection_id))
```

## 5. Error และ response envelope

- use case `raise errors.DomainError(message, status)` เท่านั้น ห้ามโยน `fastapi.HTTPException`
- `main.py` แปลงทุก error เป็น SOP envelope: `DomainError` → `{success: false, message}` ตาม status, `RequestValidationError` → **400** พร้อม `errors: [{field, message}]` (ไม่ใช่ 422 default ของ FastAPI), error ที่ไม่ได้คาดไว้ → 500 ข้อความกลาง ๆ ห้ามส่ง `str(exc)` ออกไป
- success: `ApiSuccess(data=...)` และ list มี `pagination`

## 6. Async, connection และ transaction

- เปิด/ปิด resource ใน `@contextlib.asynccontextmanager` lifespan — ห้ามใช้ `@app.on_event` ที่ deprecated แล้ว
- DB pool, HTTP client, model weights สร้างครั้งเดียวเป็น singleton แล้ว inject ผ่าน `deps.py` พร้อมกำหนดขนาด pool ชัดเจน
- **ทุก network call ต้องมี timeout** เช่น `httpx.Timeout(10.0, connect=3.0)` ค่ามาจาก `Settings`
- งาน CPU หนัก (bcrypt, preprocessing ภาพ) ใน async route ให้ใช้ `asyncio.to_thread(...)`
- connection ตั้งเป็น autocommit; งานที่ต้อง commit หลาย statement พร้อมกันให้เปิด `async with self._db.transaction():` ใน use case
- อย่า commit ใน teardown ของ `yield` dependency — FastAPI รัน teardown **หลัง** ส่ง response ไปแล้ว request ถัดไปของ client อาจยังไม่เห็นข้อมูล

## 7. บังคับ boundary ด้วย test

โครง folder ไม่ได้ห้ามใครเขียน SQL ใน use case — test นี้ห้าม ใส่ใน `tests/test_layering.py`:

```python
import pathlib

APP = pathlib.Path(__file__).resolve().parents[1] / "src" / "app"
SQL = ("SELECT ", "INSERT INTO", "UPDATE ", "DELETE FROM")



def _sources() -> list[tuple[pathlib.Path, str]]:

    """
    Read every module of the service.

    Returns:
        `(path, source)` for each file under `app/`.
    """
    return [(p, p.read_text(encoding="utf-8")) for p in sorted(APP.rglob("*.py"))]



def test_sql_stays_in_the_db_adaptor() -> None:
    for path, source in _sources():
        if any(keyword in source for keyword in SQL):
            assert path.parent.name == "db", f"{path} writes SQL outside adaptor/db"



def test_entities_import_nothing_above_them() -> None:
    for path, source in _sources():
        if path.parent.name == "entities":
            assert "app.adaptor" not in source and "app.use_cases" not in source, path



def test_use_cases_never_touch_http() -> None:
    for path, source in _sources():
        if "use_cases" in path.parts:
            assert "fastapi" not in source, f"{path} imports the web framework"
```

หรือใช้ import-linter `layers` contract (ตรวจ import ทางอ้อมด้วย):

```toml
[[tool.importlinter.contracts]]
name = "backend layers point inwards"
type = "layers"
containers = ["app"]
layers = ["adaptor.http", "use_cases", "adaptor.db | interfaces", "entities"]
```

## 8. Testing (Phase 4 / 6)

| ระดับ | เครื่องมือ | สิ่งที่ทดสอบ |
|---|---|---|
| Unit | `pytest` + fake ที่ implement port | use case ล้วน ๆ ไม่มี DB ไม่มี HTTP |
| Integration | `pytest` + `testcontainers` (Postgres จริง) + `httpx.AsyncClient` | endpoint ครบ layer, SQL ตรงกับ schema จริง |
| Boundary | `test_layering.py` / `lint-imports` | ทิศทาง dependency |

- ตั้งชื่อ `test_<unit>_<scenario>_<expected>` เช่น `test_judge_missing_inspection_raises_404` — test ที่ตั้งชื่อแบบนี้ไม่ต้องมี docstring
- ห้าม `time.sleep()` ใน test ให้รอด้วย event หรือ poll เงื่อนไข
- ห้ามพึ่ง server ที่รันอยู่บน port ของเครื่อง — DB และ service ใน test มาจาก `testcontainers` บน port สุ่ม
- integration test ใช้ DDL ชุดเดียวกับ production (apply ไฟล์ SQL verbatim) เพื่อให้ schema drift ทำให้ test แดง
- แต่ละ test รันใน transaction แล้ว rollback ข้อมูล seed จึงเหมือนกันทุก test
- เขียน test ก่อน (Red) ตาม AC แล้วจึงเขียน use case (Green)

## Quality gate (ต่อ endpoint)

✅ Pydantic ครอบ body/query/params · ✅ auth guard ใน `deps.py` (หรือ comment บอกเหตุผลที่ public) · ✅ controller ไม่มี logic · ✅ use case ไม่มี `fastapi` และ SQL · ✅ SQL parameterized อยู่ใน `adaptor/db` · ✅ ระบบภายนอกผ่าน `adaptor/<system>` · ✅ port มีเหตุผลตามข้อ 3 · ✅ network call มี timeout · ✅ resource เปิดใน lifespan · ✅ SOP envelope ทุก path · ✅ layering test ผ่าน
